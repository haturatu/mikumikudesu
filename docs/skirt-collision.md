# スカートと脚の衝突補正（P0 / P1）

Bullet の接触応答を修正し、スキニング後のスカート表面に共通 Compute Pass を追加します。
Preview は補正後のバッファを Shadow / Normal / Main / Edge で共有し、Native は補正後の位置から
BLAS を更新します。既存の剛体・ジョイント・ボーンへの物理反映を維持します。

## P0: キネマティック速度と物理の精度

- サブステップ直前に interpolation transform を上書きしません。Bullet が前の姿勢から並進・角速度を計算します。
- reset / teleport では interpolation transform と速度をリセットし、シークの移動を接触速度にしません。
- 特定した脚のカプセルについて、時間、最短回転角（5度/step）、移動量（半径の0.25/step）の最大値から
  サブステップを選びます。動作による追加は16までとし、従来の固定時間による必要ステップ数は削減しません。
- スカートと脚を特定できたモデルのみ solverIterations を25にします。その他は従来の10です。
- `MmdPhysics::stepStats()` は実際のステップ数、動作予算の超過、PMX剛体IDと接触深度を返します。
  接触数は全サブステップの接触点数で、同じ剛体ペアが繰り返し含まれます。

libmmd はマージ済みの物理修正を含む [v0.2.7](https://github.com/haturatu/libmmd/tree/v0.2.7) を参照します。

## P1: 表面とカプセルの補正

`identifySkirtCollision()` は動的スカート剛体、脚・ひざのキネマティックカプセル、双方の衝突マスクを調べます。
材質名に skirt / スカート / 裙 があれば、その材質を対象にします。別材質の発光ラインや装飾も、
スカート剛体に接続するボーンのウェイトから抽出します。ウェイトのあるインデックスが15%を超える材質は全体を選び、
それ以下のコートなどはウェイトが0.2を超える頂点に接する三角形だけを選びます。足首は対象から除きます。
YYB式初音ミクv1.02では1,069頂点、1,330三角形、16スカート剛体、4脚カプセルです。
名前付きSkirtの895頂点に加え、luminous02とClothes01/02のスカート部分も補正します。

- カプセルの中心線は剛体のローカルY軸を回転させて作ります。位置、半径、余裕0.03をメッシュと同じ座標系に変換します。
- PMXの脚剛体は実際の太ももより短く細い場合があります。脚ボーンのウェイトが0.2以上の対象外頂点と、
  その頂点に接する三角形を抽出し、GPUスキニング後の位置から半径・端点を毎フレーム広げます。
  スカート頂点は脚の抽出に含めません。三角形を含む脚表面が収まる包絡カプセルに、さらに0.0075の余裕を確保します。
  半径最大の頂点で端点の平方根が不安定にならないよう、端点も余裕を含む包絡形状から計算します。
  PreviewとNativeは、それぞれ描画に使う変形済みバッファから同じCompute Passで形状を求めます。
- モデルの腰から見た各頂点の外向き方向を保持し、腰の回転で現在の向きへ変換します。
  脚の回転はカプセルの軸に反映し、この方向を軸に垂直に投影します。前側の布を後ろへ押し込むことや、
  曲がった太ももと膝が同じ布を逆方向へ引くことを防ぎます。元の方向がない入力では履歴を使います。
  参照方向が水平に上げた脚の軸と平行になる付近では、直交する方向を経由して切り替え、
  反対向きのベクトルの補間がゼロになって隣接頂点の補正方向が反転することを防ぎます。
- 初期化で頂点を押し出し、接触拘束と近傍の補正量の平滑化を最大6反復行います。
  深い接触では、脚の反対側へ抜けて距離判定が外側になっていても、半径の1.5倍以内で元の側へ戻します。
  内向きの半径方向成分だけを反射し、接触点の横方向と端点の軸方向を維持します。
  端点の方向まで反転して布を上げた脚の先へ引き上げないようにし、補正方向のレイと球面の交点まで動かします。
- 三角形とカプセル中心線の最短距離を検査します。端点・辺・面内部の交差も検出するため、
  頂点や重心が外側でも三角形が脚を横切るケースを検出できます。
  計算はカプセルを原点とする座標で行い、面・辺の退化判定は形状の大きさに応じた許容値を使います。
  描画用の正規化で小さくなった三角形も、面内部の貫通を検出します。
- 回復処理では隣接する三角形の外向き支持平面を順に満たし、平滑化で貫通を再発させません。
  各頂点は支持平面に対する自身の不足分だけ動き、既に外側にある頂点を過剰に押し出しません。
  中心線を横切る深い接触では隣接面の参照方向をまとめた支持平面も使います。
  最後の頂点投影は幾何学的な最短方向を使い、頂点ごとの参照方向が三角形の回復を打ち消さないようにします。
  局所拘束は固定の隣接三角形数で平均化します。各頂点が自分の結果だけを書き、
  反復間は別のバッファを読み書きします。
- 腰に従う頂点の移動率は0.25、スカートの物理ボーンに従う頂点は最大1です。
  総補正量は最大脚半径の6倍までに制限し、残る貫通を診断に記録します。
- 最後に面積で重み付けした法線を更新します。材質の元の法線方向を維持し、対象外の頂点は変更しません。
- 初回、シーク、逆再生、繰り返しフレーム、モデル構成の変更では履歴を初期化します。

`SkirtVertex::outwardNormal` はSNORM16のoctahedral encodingと有効フラグです。
`SkirtCapsule` は96バイトで、`surfaceRotation` が腰の回転です。前フレームの端点は `previousA/B.xyz`、
2つの `w` は参照方向のない入力の回復用法線です。現在の `aRadius.w` と `bMargin.w` は半径と余裕です。

フレームごとの入力と作業領域はframe slotごとに持ち、履歴だけを共有します。
スキニング→補正、反復間、前フレームの履歴→次フレームにメモリ依存を置きます。
Previewのasync computeでも描画が補正後の出力を待ちます。Nativeの通常フレームは
`record(commands, upload, generation)` で補正を行い、その後BLAS更新の依存を置きます。
引数なしの旧 `record(commands)` はスキニングのみの互換経路です。

## 品質と診断

既定は32反復です。Preview / Native / 動画書き出しで同じ値を使用します。

```bash
./build/linux-debug/mikumikudesu --skirt-collision-iterations 32 --asset "$PMX" --asset "$VMD"
./build/linux-debug/mikumikudesu --skirt-collision-iterations 16 --asset "$PMX" --asset "$VMD"
./build/linux-debug/mikumikudesu --skirt-collision-iterations 0 --asset "$PMX" --asset "$VMD"
```

範囲は0〜64で、0は表面補正を無効にします。少ない反復は処理時間を減らしますが、急な足上げやシークで
貫通が残る場合があります。今回のYYB / UNDEADの合格値は既定の32です。
`SkirtCollisionUpload::iterations = 0` はテスト用の診断のみの経路で、CLIの無効化とは区別します。

`skirtRigidStats()` と、GPU完了後の `SkirtCollisionRuntime::readStats()` / `readCapsules()` / Previewの診断APIで、
剛体の接触数と深度、貫通頂点・三角形数、メッシュの最大深度、総補正距離を取得できます。
通常描画では診断のreadbackによる待機を入れません。メッシュの判定深度には0.03の余裕を含みます。脚メッシュの包絡形状からは、さらに0.0075広げたカプセルで判定します。

## 回帰テスト

```bash
cmake --preset linux-debug
cmake --build --preset linux-debug
ctest --test-dir build/linux-debug --output-on-failure

PMX='/path/to/yyb-miku.pmx'
VMD='/path/to/UNDEAD.vmd'
VK_LAYER_VALIDATE_SYNC=1 ./build/linux-debug/dayo_skirt_collision_tests \
  "$PMX" "$VMD" /tmp/yyb-skirt.csv
```

DXCと取得済みMikuMikuDayoヘッダーがあればNativeのスキニングも検証します。
アセットはリポジトリに含めません。GPUのないCIでは既存のVulkanテストと同様に実行環境を用意します。

- 合成データ: 双方向のマスク、材質の範囲、回転と正規化、頂点・三角形のみの貫通、
  履歴の側、距離だけでは検出できない反対側への脱出、腰と脚の回転の分離、シーク、退化形状、脚剛体の外側にある描画頂点への形状フィットとその履歴、
  Preview / Nativeのバッファ配置、GPUスキニングから描画出力までの接続。
  端点の接触で布を脚の先へ引き上げないことと、1/10,000に縮小した三角形の面接触も検証します。
- 実アセット: 0〜348を1/30秒で評価し、独立した物理ワールドで同じ結果になることを確認します。
  その後0→127をシークします。全フレームでPreview / Nativeの配置による補正済み位置を比較します。
  描画用の正規化座標でも補正位置と診断を検証します。
  抽出した脚表面の全頂点が、フィットしたカプセルに0.0075の余裕を残して収まることも検証します。
  最大判定深度の合格値は0.031未満です。余裕0.03 + 包絡形状からの距離0.0075より小さいので、脚表面との距離を確保できます。
- 0、115、120、127、130、140、150、165、348とシークで、CPU / Preview GPU / Native GPUの
  実際のスキニングと補正を比較します。CPU/GPUの許容差はPMX座標で0.002、同一入力の補正パスは0.00001です。
- CSVに毎フレームの剛体・メッシュの診断とステップ数、正規化座標の深度と位置差を記録します。
  123フレームおよび深度が0.031を超えた場合は
  `.mesh.csv` / `.capsules.csv` に詳細を保存します。`.triangles.csv` は頂点ID、`.timing.csv` はGPU時間です。
- 調査用に `DAYO_SKIRT_FIRST_FRAME` / `DAYO_SKIRT_LAST_FRAME` / `DAYO_SKIRT_ITERATIONS` を指定できます。
  合格判定には指定なしの全フレームを使います。

## 実測結果

YYB式初音ミクv1.02 + 指定UNDEAD、Bullet、Vulkan validation / synchronization validation、既定32反復での結果です。
補正前は、このPRの物理設定でスキニングした直後のメッシュです。

| 条件 | 補正前の最大深度 | 補正後の最大判定深度 | 補正後の貫通頂点数 |
| --- | ---: | ---: | ---: |
| 通常再生0〜348 | 1.43273 | 0.030032 | 0 |
| 右足115〜140 | 1.43273 | 0.0300263 | 0 |
| 左足150〜165 | 0.476682 | 0.0300248 | 0 |
| 0→127シーク | 1.18526 | 0.0300298 | 0 |

脚表面の包絡形状から0.0075広げたカプセルに、判定の余裕0.03を加えた深度です。
すべて0.0375より小さいため、検証した脚表面の包絡形状への貫通はありません。
小さな三角形接触の診断は余裕領域への接触です。通常再生の物理ステップ数は最大11でした。
全フレームでNaN・無限大はなく、Preview/Nativeの配置による位置比較が合格しました。
重点フレームでのCPU/GPUスキニングの比較も合格しました。最大位置差はCPU/Preview GPUで0.00000393391、
Native/Preview GPUで0.00000572205でした。描画用の正規化とPMX座標の補正位置差は全フレームで最大0.000578403でした。
glslcで共有シェーダーをビルドしたRelease版でも、全349フレームとシークが合格しました。

AMD Radeon Vega 8 / RADV、Release、validation有効、フレーム127の30回の測定（最初の6回を除く中央値）では、
同じ描画処理に補正を足したGPU時間は1.858ms→31.578ms、増分29.721msでした。
これはフレーム127の追加Compute処理を含む測定で、通常再生全体の平均FPSではありません。
CPU負荷・GPUクロック・validation・ハードウェアによって変動します。

有効なCTest 23件はすべて合格しました。RadeonでのPreviewとllvmpipeでのNative（実際のBLAS更新を含む）で、
123フレームのMP4書き出しも成功しました。指定のRelease実行ファイルで120〜348を連続書き出しし、
123、127、134、140、165、300、348の画像を確認しました。
123では補正対象1,330三角形と描画後のBody01を使った独立の辺・面交差検査も0件でした。
この単一フレームの身体メッシュ検査と、全フレームのカプセル診断は別の検証です。
Vulkan同期検証にエラーはありませんでした。

## 適用範囲

この処理は剛体ボーンのアニメーションを維持する表面補正です。脚が激しく入り込む場合には布が伸びることがあります。
脚の衝突形状は抽出した描画メッシュを包むカプセルです。任意の人体メッシュとの正確な三角形同士の衝突ではありません。
自動判定に使う名前やウェイトが異なるモデルは対象抽出の追加が必要です。
XPBD、布の伸長・曲げ拘束、自己衝突、物理状態キャッシュは今回のP0/P1には含めません。
