# Preview のゼロ法線回帰テスト

PMX 頂点の法線が `(0, 0, 0)` であっても、頂点位置にはモーフ、スキニング、モデル配置、カメラ変換、射影を適用する必要があります。法線が退化している場合は、シェーディング用に `(0, 0, 1)` を代替値として使用します。

背景描画かどうかは法線の値から推測せず、明示的な push constant で判定します。

## 不具合の再現条件

問題の確認に使用した `Vivian.pmx` は 31,709 頂点、117,111 インデックスを持ちます。頂点 9446 の法線だけが正確にゼロです。

| 項目 | 値 |
| --- | --- |
| 位置 | `(0, 16.691345, 0.785809)` |
| 法線 | `(0, 0, 0)` |
| UV | `(0.927500, 0.342600)` |
| ウェイト | BDEF2、ボーン 8 / 9、約 0.835283 / 0.164717 |
| 材質 | `体` |
| 共有する三角形 | 10 個 |

修正前は、法線による背景判定が誤って適用され、当該頂点のクリップ空間位置が `(0, 16.691345, 0, 1)` になっていました。その結果、接続する三角形が画面外へ引き伸ばされていました。

修正後は背景用の明示的なフラグで判定します。元の PMX ファイルは変更せず、リポジトリにも含めません。

## 自動テスト

`preview_render` テストでは、報告された頂点データを含む小さな triangle fan を構築し、+Z 方向の単位法線を持つ同等のメッシュと GPU readback のピクセル値を比較します。正常に描画された参照ジオメトリも必要です。

次の条件を検証します。

- 変形済み頂点と BDEF1 / BDEF2 / BDEF4 / SDEF / QDEF
- ゼロ法線とゼロに近い法線
- 透視投影と正射影、カメラの回転・移動
- 輪郭描画と法線デバッグ表示
- モデルの分離表示・法線デバッグ時の背景テクスチャ

ボーン 8 / 9 には並進を与え、位置変換を検証します。合成 BDEF4 / QDEF ケースで使う非ゼロの影響ボーンは 2 本です。そのため、4 本の独立した骨変換との数値一致までは検証しません。

## 外部モデルでの追加検証

元の Vivian モデルが手元にある場合は、次の環境変数を指定します。

```sh
DAYO_TEST_VIVIAN_PMX="$HOME/Downloads/vivian/Vivian.pmx" \
  ctest --test-dir build/linux-debug -R '^preview_render$' --output-on-failure
```

このテストはモデルの頂点数・インデックス数、ゼロ法線、頂点を共有する 10 個の三角形を検査したうえで、材質とボーン移動を制御して元の頂点位置・法線を描画します。

**制限:** この追加テストで確認するのは位置の処理であり、モデル全体のアニメーション、物理演算、テクスチャの正しさではありません。CI は外部素材を必要としない合成 fixture だけを実行します。
