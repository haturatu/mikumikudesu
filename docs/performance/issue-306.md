# #306: テクスチャ累積位置の再走査を除く

従来は評価対象モデルごとにscene先頭から自身までtextures.size()を加算していた。
N個のモデルで最大N(N-1)/2回の加算となり、PreviewとNativeの両方に同じ処理があった。

scene順の累積オフセットを保持し、フレーム冒頭でモデルIDとテクスチャ数を一度だけ照合する。
構成が変わった場合だけO(N)で再構築し、各評価モデルは保存したscene indexからO(1)で取得する。
ジオメトリのないモデルや同じPMXの別インスタンスも累積位置に含む。
slot 0のfallbackと既存のtexture/sphere/toonへの+1は維持する。

テクスチャ数変更は材質テンプレートの世代にも反映する。
再読み込みは個数が同じでも有効な画像の有無が変わり得るため、材質テンプレートを無効化する。

検証: prefix値、空モデル、同じパスの複数個体、順序変更、削除、個数の変わる再読み込み、
変更なしの世代維持を単体テスト。アプリのnative切替/モデル追加削除テストも実施する。
小規模シーンのFPS向上率は未計測で主張しない。採用根拠は再走査回数の上限が二次から線形になること。
